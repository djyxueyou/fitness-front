# FitForge 阶段 B 补充设计：热身组、推荐覆盖反馈与小程序休息提醒

## 1. 目标

在阶段 B 已有训练页能力基础上，补齐三类体验细节：

- 优化热身组生成方式，让用户先看到建议再插入，并理解热身组不影响训练统计。
- 在用户应用进阶建议后又修改目标时，向后端记录 `OVERRIDDEN`，用于后续优化推荐质量。
- 休息提醒先按微信小程序和 H5 可稳定支持的能力实现，不做后台强通知。

核心原则：

- 训练主流程不能被额外弹窗阻塞。
- 推荐状态、反馈状态和长期目标的核心逻辑由后端处理。
- 前端只负责交互展示、临时草稿状态、可用能力检测和用户行为触发。

## 2. 范围

### 包含

- 热身组建议底部面板。
- 本地热身组候选计算和插入确认。
- 已有热身组的管理入口。
- 应用推荐后的目标快照记录。
- 用户修改推荐目标后的 `OVERRIDDEN` 上报触发规则。
- 后端反馈状态从 `APPLIED` 升级为 `OVERRIDDEN` 的处理约束。
- 小程序内休息倒计时、震动提醒、提示音能力检测、回到页面后的时间补算。
- 训练设置中与本阶段相关的轻量设置项。

### 不包含

- 数据库迁移文件调整。
- 小程序订阅消息提醒。
- 原生 App 后台通知、锁屏通知、系统级长驻计时。
- 按动作类型配置不同休息时长。
- 多套热身算法模板。
- 复杂的推荐质量分析后台。

## 3. 热身组底部面板

### 3.1 入口

训练页动作卡片保留 `生成热身组` 入口。

点击后不再直接插入热身组，而是先计算候选热身组并打开底部面板。

如果当前动作不适合生成热身组，直接给轻提示：

- 自重动作：`自重动作建议直接开始，也可以手动添加适应组。`
- 计时动作：`计时动作暂不生成热身组。`
- 没有正式组重量：`请先设置第一个正式组重量。`
- 已有已完成热身组：`已完成的热身组不能重新生成。`

### 3.2 面板结构

底部面板展示：

- 标题：`建议热身组`
- 副文案：`根据第一个正式组计算，热身组不计入容量、完成率和进阶判断。`
- 候选列表：按组展示重量和次数，例如 `20kg × 10`
- 主按钮：`插入热身组`
- 次级按钮：`取消`

如果当前动作已经有未完成热身组，入口文案改为 `热身组 2组`，点击后打开管理面板：

- `继续调整热身组`：关闭面板，用户直接修改现有热身组。
- `重新生成`：先删除未完成热身组，再按当前第一个正式组重新计算。
- `删除全部热身组`：删除未完成热身组。
- `取消`

已完成热身组不允许重新生成或删除，避免修改已经发生的训练记录。

### 3.3 生成规则

热身组由前端根据当前动作第一个正式组计算，插入后仍以 `WARMUP` set type 保存。后端只需要识别 `WARMUP` 并排除统计、进阶判断和正式组完成率。

规则：

| 第一个正式组重量 | 热身组 |
| --- | --- |
| `< 30kg` | 50% × 8-10 |
| `30kg - 59.9kg` | 50% × 8，75% × 5 |
| `60kg - 99.9kg` | 40% × 8，60% × 5，80% × 3 |
| `>= 100kg` | 40% × 8，60% × 5，75% × 3，90% × 1-2 |

重量取整：

- kg 默认按 `2.5kg` 步长取整。
- lb 默认按 `5lb` 步长取整。
- 后续读取用户训练设置中的重量步长。

次数规则：

- 低强度热身组使用 8-10 次。
- 中等热身组使用 5 次。
- 接近正式重量的热身组使用 1-3 次。
- 生成次数不得高于第一个正式组次数。

插入规则：

- 插入到第一个正式组前。
- `setType = WARMUP`
- 默认 `done = false`
- 不自动完成。
- 不复制推荐状态。
- 不触发 `OVERRIDDEN`。

## 4. 应用推荐后的覆盖反馈

### 4.1 设计目标

用户点击 `应用建议` 代表接受推荐方向。若随后又修改重量、次数、时长或正式组数量，说明推荐目标不完全合适。系统应记录这类反馈，供后端后续优化推荐规则。

该反馈不应该打断训练，也不应该让用户额外确认。

### 4.2 前端状态

前端在用户成功应用推荐后，为该动作保存一份本地快照：

```ts
interface AppliedRecommendationSnapshot {
  exerciseId: number
  recommendationId: string
  appliedSets: Array<{
    setType: 'NORMAL'
    weight?: number
    reps?: number
    durationSeconds?: number
  }>
  dirtyAfterRecommendation: boolean
  overrideReported: boolean
}
```

只记录正式组快照，不记录热身组。

### 4.3 什么算修改

应用推荐后，以下行为会把该动作标记为 `dirtyAfterRecommendation = true`：

- 修改正式组重量。
- 修改正式组次数。
- 修改正式组时长。
- 添加或删除正式组。

以下行为不算覆盖：

- 完成组。
- 修改热身组。
- 填写余力反馈。
- 打开或关闭推荐卡片。
- 应用推荐前的任何修改。
- 点击 `先不处理` 后的修改。

### 4.4 上报时机

前端不在每次输入变化时上报。用户从 `10` 改到 `11` 再改到 `15`，只应该形成一次覆盖反馈。

前端只在以下时机检查一次：

- 用户完成该动作第一组正式组。
- 用户点击 `完成此动作`。
- 用户切换到其他动作。
- 用户保存并结束训练。
- 用户退出训练并保存草稿前。

如果当前正式组目标和应用快照不同，并且 `overrideReported = false`，前端调用后端反馈接口：

```ts
action = 'OVERRIDDEN'
```

调用成功或后端返回已处理后，前端都把 `overrideReported` 置为 `true`，避免重复打扰接口。

### 4.5 后端规则

核心反馈状态由后端处理。

后端应支持同一 `userId + recommendationId` 的状态升级：

- 初始：`APPLIED`
- 如果收到 `OVERRIDDEN`：将原记录升级为 `OVERRIDDEN`

不建议为同一 recommendation 保存多条事件流水。当前阶段只需要知道最终状态：

- `APPLIED`：用户应用并基本按建议执行。
- `DISMISSED`：用户明确不采用。
- `OVERRIDDEN`：用户应用后又修改目标。

如果后端已经存在 `APPLIED`，再次收到 `OVERRIDDEN` 时应更新原记录，而不是因为唯一约束报错。

后端不应该因为反馈记录失败阻塞训练保存。

## 5. 小程序休息提醒

### 5.1 设计边界

休息提醒先按小程序可稳定支持的能力实现：

- 页面前台倒计时。
- 倒计时结束时震动。
- 可用时播放短提示音。
- 页面内浮层或 toast 提醒。
- 回到页面时根据时间差补算剩余时间。

不做：

- 小程序订阅消息。
- 后台长驻计时。
- 锁屏通知。
- 系统通知栏提醒。

### 5.2 前台交互

完成正式组后启动休息倒计时：

- 展示休息浮层。
- 显示休息标题，例如 `第 2 组已完成`。
- 显示剩余时间。
- 操作：`+30秒`、`跳过`。

倒计时结束：

- 自动清空倒计时状态。
- 调用震动能力。
- 如果提示音开启且平台支持，播放短提示音。
- 显示 `休息结束，开始下一组`。
- 如果有目标动作，聚焦该动作卡片。

### 5.3 超级组

超级组内切换动作时不启动完整休息。

完成超级组一轮后启动休息：

- 标题：`超级组一轮已完成`
- 到时提示：`休息结束，开始下一轮`

### 5.4 页面切后台和返回

前端保存：

- `restStartedAt`
- `restDurationSeconds`
- `restTitle`
- `restFocusIndex`

页面隐藏时不承诺持续提醒。

页面恢复时：

- 根据当前时间和 `restStartedAt` 计算剩余时间。
- 如果未超时，恢复倒计时。
- 如果已超时，显示 `休息已结束`，并聚焦目标动作。

### 5.5 设置项

设置入口：`我的 > 设置 > 训练设置`

本阶段建议加入：

- 默认休息时间。
- 休息结束震动：开/关。
- 休息结束提示音：开/关。
- 重量调整步长。
- 次数调整步长。
- 时间调整步长。
- 默认杠铃杆重量。

这些设置优先保存在用户偏好中；未登录或接口失败时，前端可保留本地值，但不影响训练记录保存。

## 6. 数据流

### 6.1 热身组

```text
点击生成热身组
-> 前端读取当前正式组目标
-> 前端计算候选热身组
-> 用户确认插入
-> 前端插入 WARMUP sets
-> 保存训练时提交 setType
-> 后端保存 setType
-> 后端统计和推荐时排除 WARMUP
```

### 6.2 推荐覆盖反馈

```text
用户应用建议
-> 前端调用 APPLIED
-> 后端保存反馈并更新用户-动作进阶目标
-> 前端保存应用快照
-> 用户修改正式组目标
-> 前端标记 dirty
-> 用户执行或离开该动作
-> 前端比较当前目标与快照
-> 前端调用 OVERRIDDEN
-> 后端将反馈状态升级为 OVERRIDDEN
```

### 6.3 休息提醒

```text
完成正式组
-> 前端启动休息倒计时
-> 页面前台：倒计时结束后震动/提示音/浮层
-> 页面后台：只保存开始时间和持续时间
-> 页面恢复：按时间差补算并展示结果
```

## 7. 验收标准

- 点击 `生成热身组` 后先出现建议面板，而不是直接插入。
- 用户能看到每一组建议重量和次数。
- 插入后的热身组为 `WARMUP`，不计入总容量、正式组完成率和进阶推荐。
- 已完成热身组不能被删除或重新生成。
- 应用建议后，用户修改正式组目标不会立即请求后端。
- 用户完成正式组、切换动作、完成动作、结束训练或保存草稿前，会检查是否需要上报 `OVERRIDDEN`。
- 同一 recommendation 最多形成一次 `OVERRIDDEN`。
- 后端允许 `APPLIED` 升级为 `OVERRIDDEN`。
- 休息倒计时支持 `+30秒` 和 `跳过`。
- 小程序前台倒计时结束后有震动或页面内提示。
- 页面从后台恢复后能正确补算休息剩余时间。
- 以上增强失败时，不影响训练组记录和训练保存。
