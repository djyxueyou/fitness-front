# FitForge 我的页与训练信息架构设计

## 目标

将“我的”Tab 重构为简洁、接近 iOS inset grouped list 的个人中心，同时明确计划、模板、训练日历和历史记录的归属。实现以用户选定的视觉方案 1 为基准，并沿用现有橙色品牌色与四项 Tab Bar。

## 信息架构

- “我的”只承载个人身份、训练成就、健康资料、账户与服务。
- “模板管理”从“我的”移入“计划”业务域，入口命名为“训练模板”。
- “历史记录”不再作为“我的”独立入口，与训练日历共用同一训练记录数据和详情页。
- 训练记录提供日历与列表两种查看方式：日历回答“哪天练了”，列表回答“最近练了什么”。
- “计划”负责未来训练安排；“训练记录”负责过去训练结果；“我的”负责个人与账户。

## 我的页结构

页面采用浅灰系统背景、白色分组容器、轻分隔线和统一线性图标。橙色只用于等级进度与 Tab 选中态。

### 个人与训练概览

- 页面使用大标题“我的”。
- 顶部个人概览整组可点击并进入个人资料。
- 展示头像、昵称和训练等级。
- 等级与三项统计合并在一个容器内，避免卡片嵌套。
- 统计保留连续训练、累计训练、累计容量。

### 健康资料

- 个人资料。
- 身体指标。

### 账户与服务

- 会员中心。
- 我的收藏。
- 设置。
- 关于。

历史记录和模板管理不在此页面展示。

## 计划页后续结构

- 顶层提供“计划 / 日历”视图切换。
- 当前计划仍是计划页首要区域。
- 推荐计划与我的计划保留为计划列表内的二级切换。
- “训练模板”作为计划页中的独立入口进入模板列表，不与计划卡片混排。
- 日历视图内提供“日历 / 列表”切换，二者进入同一训练详情页面。

本轮实现优先完成“我的”页重构和入口迁移所需的前端导航调整。计划页当前存在用户未提交修改，实施时必须先核对并保留这些改动，再决定模板入口的最小安全落点。

## 视觉规范

- 背景沿用浅色主题变量，目标观感接近 iOS grouped settings。
- 页面横向安全边距使用现有 Tab 页面尺度，视觉目标约为 16pt。
- 分组容器圆角约 12–16pt，不使用明显投影。
- 列表行最小视觉高度 44pt，整行可点击。
- 正文以 15–16pt 等效字号为基准；辅助文字必须保持可读对比度。
- 使用项目已有图标资源或统一图标方案，不再使用 Emoji 或文本符号模拟图标。
- 保持现有暗色主题能力，不写死只适用于浅色主题的文本和背景颜色。

## 行为与状态

- 鉴权、资料刷新、等级详情、退出登录和训练草稿入口保持现有行为。
- 个人概览点击进入个人资料；等级区域仍可进入等级详情。
- 所有列表行继续通过现有 route 常量导航。
- 加载、未登录跳转和接口失败行为不改变。

## 验收标准

- “我的”页不再展示历史记录和模板管理入口。
- 页面不出现卡片套卡片、Emoji 图标或多余彩色图标底板。
- 个人资料、身体指标、会员中心、收藏、设置和关于均可正常进入。
- 等级详情、统计数据、主题切换和 Tab Bar 行为保持正常。
- H5 与微信小程序构建不出现模板或样式错误。
- 前端格式检查和 TypeScript 检查通过。
- 视觉检查确认常见手机宽度下无裁切、重叠或底部 Tab 遮挡。

## 非目标

- 本轮不修改后端接口或数据结构。
- 本轮不重做等级详情弹层。
- 本轮不新增训练记录数据模型。
- 本轮不重绘整套 Tab Bar 图标。
