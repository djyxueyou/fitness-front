# FitForge 产品优化总纲设计

## 1. 文档目的

本文定义 FitForge 下一阶段产品优化的统一目标、范围、设计原则、交付顺序与验收口径。详细功能分别由四份子方案描述：

1. `2026-06-14-fitforge-activation-first-workout-design.md`
2. `2026-06-14-fitforge-efficient-workout-progression-design.md`
3. `2026-06-14-fitforge-review-history-offline-design.md`
4. `2026-06-14-fitforge-pro-membership-sharing-design.md`

本文是产品、设计、前端和后端共同遵循的上层约束，不直接替代子方案中的具体交互与数据契约。

## 2. 产品目标

FitForge 面向刚开始力量训练和处于进阶初期的用户，核心承诺是：

> 每次打开都知道今天练什么，训练中能快速完成记录，训练后知道下一次如何进步。

下一阶段不以增加功能数量为目标，而是优化三条关键路径：

1. 首次进入后快速获得可执行计划并完成第一次训练。
2. 训练中减少输入成本，并提供可解释的渐进建议。
3. 训练后形成周复盘、下一步行动和合理的 Pro 转化。

## 3. 已确认范围

### 3.1 本阶段包含

- 首次使用画像采集与推荐计划。
- 调整基础训练记录的免费边界。
- 产品事件埋点。
- 数据导出、数据删除与账号注销入口。
- RPE/RIR、可解释的渐进超负荷建议。
- 一键沿用上次表现、热身组、配片计算、超级组等训练效率能力。
- 周训练复盘、错过训练后的恢复安排。
- 离线训练与待同步状态。
- 高级训练分析、会员权益重构。
- 训练总结、周复盘和计划的轻量分享。

### 3.2 本阶段明确不包含

- 密钥修复。
- CI 建设。
- 数据库迁移工具建设。
- 修改修为成长的结算规则。
- HealthKit 和 Health Connect。
- 教练版和创作者计划市场。
- 公共动态社区。
- 完整营养管理。
- AI 聊天助手。

## 4. 设计原则

### 4.1 唯一主行动

首页、计划推荐、训练中和训练总结页面，每个状态只突出一个主要行动。次级入口不得与主行动使用相同视觉权重。

### 4.2 先结论，后数据

分析和复盘页面先告诉用户发生了什么、下一步做什么，再展示支持结论的数据和图表。

### 4.3 推荐必须可解释

任何计划、重量、次数或排程建议都必须说明依据，并允许用户保持原值或手动调整。系统不得静默修改用户训练。

### 4.4 高级能力渐进披露

RPE/RIR、热身组、超级组和配片计算默认不阻塞基础记录。新手可忽略，高频用户可主动开启。

### 4.5 核心记录不被付费阻断

用户可以不限次数完成和保存基础训练。付费价值来自更好的建议、分析、配置和效率，而不是阻止用户形成习惯。

### 4.6 复用现有业务边界

- 保留四个主 Tab：首页、计划、动作库、我的。
- 保留现有训练计划、模板、动作库、训练记录和分析模块。
- 继续使用现有主题变量和公共组件。
- 后端继续采用模块化单体，不为本方案拆分微服务。

## 5. 目标用户与关键场景

### 5.1 主要用户

训练经验不足一年，希望规律进行力量训练，但缺少稳定计划和进阶判断能力的用户。

### 5.2 次要用户

已有固定训练习惯，希望更高效记录、查看趋势并获得轻量进阶建议的用户。

### 5.3 核心场景

| 场景 | 用户问题 | 产品回答 |
| --- | --- | --- |
| 第一次进入 | 我该从哪里开始？ | 采集少量条件，给出一套推荐计划和第一训练日 |
| 打开首页 | 今天应该练什么？ | 展示唯一主行动和推荐原因 |
| 训练进行中 | 上次练了多少？这次填什么？ | 显示上次表现、建议值和快速记录控件 |
| 错过训练 | 计划是不是废了？ | 提供补练、改期、跳过三个明确选择 |
| 完成训练 | 我有进步吗？ | 展示本次变化、周进度和下一次建议 |
| 考虑付费 | Pro 对我有什么帮助？ | 用真实训练结果和可获得能力解释价值 |

## 6. 核心用户闭环

```text
首次画像
  -> 推荐计划
  -> 预览第一周
  -> 启用计划
  -> 开始第一次训练
  -> 快速记录与可解释建议
  -> 完成训练
  -> 查看本次结果
  -> 周复盘与下次行动
  -> 继续训练或调整计划
```

任何新增能力必须能够说明其服务于闭环的哪个环节。无法服务核心闭环的需求不进入本阶段。

## 7. 信息架构

### 7.1 首页

- 未完成首次画像：主行动为“生成适合我的计划”。
- 已有推荐未启用：主行动为“查看推荐计划”。
- 今日有计划：主行动为“开始今日计划”。
- 有草稿：主行动为“继续训练”。
- 今日已完成：主行动为“查看训练总结”或“查看下次安排”。
- 次级入口保持“选模板、自由练、训练分析”。
- 本周节奏展示一句结论和一个进入周复盘的入口。

### 7.2 计划

- 当前计划摘要继续展示当前周、完成进度和下一训练日。
- 新增推荐计划结果和推荐原因。
- 对错过训练的计划日提供恢复安排入口。
- 自定义编辑继续放在计划详情和管理操作中。

### 7.3 训练中

- 当前动作和当前组始终优先。
- 上次表现、本次目标和推荐值在同一上下文展示。
- 高级工具通过动作菜单或工具面板进入。
- 离线状态和待同步状态清晰可见，但不打断训练。

### 7.4 我的

- 数据与隐私集中管理导出、删除和注销。
- 会员页强调结果价值。
- 高级分析仍由训练分析入口进入，不增加新的主 Tab。

## 8. 统一状态模型

### 8.1 首次画像状态

| 状态 | 含义 | 首页主行动 |
| --- | --- | --- |
| `NOT_STARTED` | 未开始画像 | 生成适合我的计划 |
| `IN_PROGRESS` | 已保存部分答案 | 继续完善训练方案 |
| `RECOMMENDED` | 已生成推荐但未启用 | 查看推荐计划 |
| `ACTIVATED` | 已启用计划 | 由计划状态决定 |

### 8.2 推荐状态

| 状态 | 含义 |
| --- | --- |
| `AVAILABLE` | 有可应用建议 |
| `APPLIED` | 用户已应用 |
| `DISMISSED` | 用户保持原值 |
| `OVERRIDDEN` | 用户应用后又修改 |
| `UNAVAILABLE` | 数据不足，不展示建议 |

### 8.3 同步状态

| 状态 | 含义 | 用户可见反馈 |
| --- | --- | --- |
| `LOCAL_ONLY` | 仅存在本地 | 已保存到本机 |
| `PENDING` | 等待上传 | 等待同步 |
| `SYNCING` | 正在上传 | 正在同步 |
| `SYNCED` | 已上传 | 不额外打扰 |
| `CONFLICT` | 服务端存在冲突版本 | 选择保留版本 |
| `FAILED` | 上传失败 | 重试同步 |

## 9. 产品指标体系

### 9.1 北极星指标

**每周完成至少两次有效训练的活跃用户数。**

有效训练定义为：

- 至少包含一个动作。
- 至少完成三组，或完成一个计时动作。
- 保存成功或已进入待同步队列。

### 9.2 激活指标

- 首次画像开始率。
- 首次画像完成率。
- 推荐计划查看率。
- 推荐计划启用率。
- 注册后 24 小时首次训练完成率。
- 进入首页到开始首次训练的中位时间。

### 9.3 留存指标

- D1、D7、D30 留存。
- 每周训练完成次数。
- 计划训练日完成率。
- 错过训练后的恢复率。
- 周复盘查看率。
- 下一次建议采纳率。

### 9.4 商业指标

- Pro 能力曝光率。
- 会员页查看率。
- 试用开始率。
- 试用转付费率。
- 付费用户训练完成率。
- 付费用户月流失率。

## 10. 埋点规范

事件使用稳定英文名称，属性使用结构化值，禁止将用户输入备注作为埋点属性。

所有关键事件至少包含：

- `user_id`：登录用户 ID；未登录时使用匿名设备 ID。
- `platform`：`H5`、`MP_WEIXIN`、`APP_IOS`、`APP_ANDROID`。
- `source_page`：触发来源页面。
- `occurred_at`：客户端触发时间。
- `app_version`：客户端版本。

关键事件由各子方案定义。事件失败不得阻塞业务操作。

## 11. 统一错误与空状态

### 11.1 网络失败

- 浏览类请求失败：保留上次可用数据，提供重试。
- 提交类请求失败：保留用户输入，不清空页面。
- 训练保存失败：进入本地待同步队列。

### 11.2 数据不足

- 推荐数据不足时不伪造建议，显示“完成一次训练后生成建议”。
- 高级分析数据不足时说明需要的训练次数，不展示空图表。

### 11.3 权限与会员

- 基础记录不弹会员阻断。
- Pro 能力点击后先说明价值与当前数据，再进入会员页。
- 会员状态请求失败时按免费能力运行，不影响训练保存。

## 12. 分阶段交付

| 阶段 | 核心交付 | 可独立验证结果 |
| --- | --- | --- |
| A 激活 | 首次画像、推荐计划、免费边界、埋点、数据管理 | 新用户能在一次流程内开始并完成首训 |
| B 训练效率 | RPE/RIR、进阶建议、快速记录、高级工具 | 用户能更快记录并理解下一组建议 |
| C 留存可靠性 | 周复盘、错过训练恢复、离线同步 | 用户错过训练或断网后仍能继续核心闭环 |
| D 商业增长 | 高级分析、会员价值、轻量分享 | Pro 权益可理解且不伤害免费训练习惯 |

阶段必须按 A、B、C、D 顺序推进。后续阶段可以设计并行，但不得在前置核心状态未稳定时提前上线依赖能力。

## 13. 现有能力复用与新增边界

| 领域 | 直接复用 | 需要扩展 | 需要新增 |
| --- | --- | --- | --- |
| 用户 | 个人资料、训练目标、经验等级 | 训练画像字段 | 画像草稿与推荐状态 |
| 计划 | 系统计划、计划详情、启用方式、训练日状态 | 计划匹配原因、计划日改期 | 推荐计划匹配服务 |
| 训练 | 模板目标、历史表现、训练草稿、幂等请求 ID | 训练组 RIR、离线草稿生命周期 | 进阶建议、同步队列、冲突处理 |
| 分析 | 周容量、动作趋势、肌群分布、PR | 周复盘结论、数据准备度 | 高级洞察与平台期判断 |
| 会员 | 会员状态、套餐、订单和支付 | 免费与 Pro 权益判断、触达频率 | Pro 价值解释上下文 |
| 分享 | 小程序和系统分享能力 | 计划只读预览 | 分享卡片与分享计划令牌 |
| 数据管理 | 现有训练、身体指标数据 | 设置页入口 | 导出任务、删除和注销流程 |

新增领域能力应保持在现有模块化单体中。推荐、同步和洞察可以形成独立领域包，但不得为了本方案拆分独立服务。

## 14. 跨阶段依赖

| 后置能力 | 必须先具备 |
| --- | --- |
| 推荐计划转化分析 | 首次画像、推荐 ID、产品事件 |
| 渐进超负荷建议 | 历史表现、训练组完成状态、可选 RIR |
| 周复盘结论 | 周统计、计划执行状态、PR 数据 |
| 错过训练改期 | 用户启用计划实例、计划日日期覆盖能力 |
| 离线训练同步 | 本地持久化、稳定 `clientRequestId`、服务端幂等 |
| 高级分析 | 稳定训练数据、周复盘和建议反馈 |
| 个性化会员页 | 数据准备度、权益判断、触达频率记录 |
| 分享计划 | 计划只读预览、复制计划能力 |

任何后置能力在依赖未完成时，只能进入设计和接口准备，不得以不可用占位入口提前上线。

## 15. 发布与验证策略

- 每个阶段先面向内部测试账号和少量用户开放。
- 新流程保留旧入口回退能力，直到关键指标和错误率稳定。
- 推荐规则、会员触达和试用周期必须带版本或实验标识。
- 产品事件缺失或异常时，不影响训练、计划和保存等核心操作。
- 阶段验收同时检查功能正确性、用户路径完成率和负向指标。

负向指标包括：

- 首次流程退出率。
- 训练中途退出率。
- 保存失败率。
- 同步冲突率。
- 会员提示关闭率。
- 推荐被忽略或覆盖的比例。

## 16. 总体验收标准

- 所有页面保持现有年轻、干净、偏 iOS 的亮色体系，并兼容现有深色主题变量。
- 任一核心状态下，首页只有一个主行动。
- 用户不限次数保存基础训练。
- 推荐值始终附带原因，并允许忽略或修改。
- 断网不导致当前训练记录丢失。
- 用户能够导出数据、删除训练数据并发起账号注销。
- 高级分析和会员权益不阻断基础训练闭环。
- H5、微信小程序和 App 端交互语义保持一致。
