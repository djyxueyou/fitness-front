# FitForge D3 Share Experience Optimization Design

## 背景

当前 D3 已完成分享预览 MVP：后端提供安全裁剪后的分享预览接口，前端在训练完成页、周复盘页和计划详情页展示分享弹层，并支持复制摘要。

这个版本验证了后端隐私裁剪和前端弹层 UI，但体验还不完整：弹层里的“分享”按钮目前和“复制摘要”一样都是复制文本，用户会误以为可以直接分享到微信、朋友圈或生成图片。健身产品的分享更偏展示型，第一版应该优先支持可保存、可截图、可发朋友圈的视觉分享图，而不是公开链接。

## 目标

- 明确 D3 分享能力的产品语义，避免“分享”按钮做伪分享。
- 把分享主形态从“复制文本”升级为“分享图/长图预览”。
- 补齐训练记录详情页和计划训练日的分享入口。
- 后端继续负责分享预览数据聚合和隐私裁剪。
- 不引入公开链接、share token、匿名访问页、撤销/过期机制。

## 非目标

- 不做公开 Web 分享页。
- 不做复制计划到他人账号。
- 不做社交平台 feed。
- 不做复杂海报编辑器。
- 不接入大模型生成分享文案。
- 不做历史数据迁移或旧记录兼容兜底。

## 分享类型

### 1. 训练记录分享图

入口：
- 训练完成页。
- 训练记录详情页。

展示内容：
- 训练名称。
- 日期。
- 训练时长。
- 动作数量。
- 完成组数。
- 动作列表。
- 每个动作的记录类型，例如自重次数、重量次数、计时。

默认隐藏：
- 精确重量。
- 总容量。
- 用户备注。
- 身体指标。

后续可扩展：
- 用户主动打开“展示重量”后，再由后端返回可展示字段。

### 2. 计划分享图

入口：
- 计划详情页的 `分享计划`。

展示内容：
- 计划名称。
- 计划目标。
- 难度。
- 周期。
- 每周训练日结构。
- 训练日标题。

默认隐藏：
- 个人执行进度。
- 历史训练记录。
- 私人备注。

### 3. 计划训练日分享图

入口：
- 计划详情页中某个训练日的操作菜单。

展示内容：
- 计划名称。
- 第几周。
- 周几。
- 训练日标题。
- 动作列表。
- 动作记录类型。
- 目标组数、次数或时长。

用途：
- 用户给朋友或教练看“今天练什么”。
- 用户保存为图片后发朋友圈或社交平台。

## 交互设计

### 分享弹层按钮

当前：
- `复制摘要`
- `分享`

调整为：
- `复制摘要`
- `保存分享图`

原因：
- `复制摘要` 是纯文本能力。
- `保存分享图` 明确告诉用户主动作是生成图片。
- 如果当前平台暂不支持保存图片，应展示明确 toast，而不是退回复制文本。

### 分享弹层结构

分享弹层继续复用 `ShareCardSheet`，但需要表达“图”和“文案”两种能力：

- 顶部：分享类型标题，例如 `训练分享图`、`计划分享图`、`训练日分享图`。
- 中部：图片预览卡片。
- 隐私提示：说明已隐藏哪些字段。
- 底部操作：
  - `复制摘要`
  - `保存分享图`

### 入口策略

- 训练完成页保留明显入口：`生成分享卡`。
- 训练记录详情页新增右上角或底部入口：`分享`。
- 计划详情页保留 hero 区域 `分享计划`。
- 计划训练日操作菜单新增：`分享训练日`。
- 周复盘页保留弱入口，但不作为本次重点优化对象。

## 后端设计

### 现有接口保留

- `GET /api/share/preview/workouts/{trainingId}`
- `GET /api/share/preview/weekly-review?weekStart=YYYY-MM-DD`
- `GET /api/share/preview/plans/{planId}`

这些接口继续返回安全摘要，可服务于弹层预览和复制摘要。

### 新增训练日预览接口

新增：

```text
GET /api/share/preview/plans/{planId}/days/{dayId}
```

职责：
- 校验当前用户可见该计划。
- 校验训练日属于该计划。
- 返回训练日分享预览。
- 后端决定动作字段是否可展示。

### DTO 扩展

在 `SharePreviewResponse` 上新增可选字段：

```text
visualTitle
visualSubtitle
sections
```

其中 `sections` 用于表达长图内容结构，例如动作列表。前端只负责渲染，不自己推导隐私字段。

保持兼容：
- 旧字段 `title`、`subtitle`、`summary`、`metrics`、`items`、`privacyNote`、`copyText` 保留。
- 训练图和计划图可以先复用 `items`，训练日长图再逐步使用 `sections`。

## 前端设计

### ShareCardSheet

调整：
- `share` emit 改为语义上的 `saveImage` 或保持事件名但按钮文案改为 `保存分享图`。
- 右按钮不再执行复制。
- 如果图片保存能力未实现，显示 toast：`分享图保存能力开发中，可先复制摘要`。

第一版可以先实现“预览卡 + 明确 toast”，不伪装成真正分享。

### 图片生成策略

第一阶段采用前端可控渲染，不引入复杂海报生成服务：

- 分享弹层中的预览卡就是图片设计基准。
- 后续小程序端使用 canvas 或截图能力生成图片。
- 如果 H5/开发环境不支持保存相册，保留清晰降级提示。

### 页面接入

训练记录详情页：
- 新增分享入口。
- 调用 `fetchWorkoutSharePreview(trainingId)`。

计划详情页：
- 计划 hero 区域继续使用 `fetchPlanSharePreview(planId)`。
- 训练日操作菜单新增 `分享训练日`。
- 调用新增训练日分享预览接口。

训练完成页：
- 保留现有入口。
- 按新按钮语义调整行为。

## 隐私与权限

- 分享预览接口必须登录。
- 只允许用户访问自己可见的训练、计划和训练日。
- 第一版不生成公开链接，因此不存在匿名访问。
- 默认隐藏重量、容量、备注、身体指标。
- 复制摘要和分享图都使用后端返回的安全字段。

## 错误处理

- 分享预览加载失败：toast `分享预览生成失败`。
- 保存图片能力未支持：toast `分享图保存能力开发中，可先复制摘要`。
- 训练日不属于计划：后端返回 not found 或 bad request。
- 用户无权限：后端返回未授权或 not found。

## 测试计划

后端：
- 训练日分享预览只返回该计划日安全字段。
- 训练日不属于计划时失败。
- 训练记录分享不暴露重量、总容量、备注和身体数据。
- 计划分享不暴露个人执行数据。

前端：
- `npm run typecheck`
- `npm run build:mp-weixin`
- 训练完成页分享弹层按钮文案正确。
- 训练记录详情页可打开分享弹层。
- 计划详情页可分享计划。
- 计划训练日菜单可打开训练日分享弹层。
- 保存分享图未实现时显示明确降级 toast，不复制文本冒充分享。

## 实施顺序

1. 后端补训练日分享预览接口和测试。
2. 前端分享 API 增加训练日预览方法。
3. 调整 `ShareCardSheet` 按钮文案和保存图降级行为。
4. 训练记录详情页新增分享入口。
5. 计划训练日操作菜单新增分享入口。
6. 跑后端 focused tests、前端 typecheck 和小程序构建。

## 决策记录

- D3 MVP 已完成，但当前“分享”按钮语义不完整。
- 第一版不做公开链接，避免引入匿名访问、撤销、过期和隐私风险。
- 健身 App 分享优先做图片/长图，因为更适合朋友圈和社交平台展示。
- 后端继续负责分享数据和隐私裁剪，前端不拼接敏感字段。
